# Implementation Instruction — Deployment (GCP, Terraform, Ansible, Docker)

Authoritative instruction for implementing `specs/002--deployment`.
Decisions in `plan.md` §0 are binding. App baseline: the system implemented
under `specs/001--initial-implementation` (see its `instruction.md`).

## 0. Ground Rules

- **`BROKER=toss` in production means REAL orders.** During implementation and
  acceptance, never start the trader with a `.env` containing `BROKER=toss`
  and a schedule that could fire; test with `BROKER=mock` locally and verify
  the VM's guard/schedules without forcing a decision cycle.
- All GCP-touching commands run under `ctx use quantitative-trading`
  (write shebang recipes/scripts that call it first — per AGENTS.md).
- Use the `gcloud`/`terraform`/`ansible`/`docker`/`just` binaries already
  installed locally. Terraform provider `hashicorp/google` (>= 6).
- Never commit `.env`, terraform state, inventory files with IPs is fine, but
  inventory is generated — gitignore generated artifacts.
- Follow existing code style (black line-length 120, isort, no abbreviations).

## 1. Application Changes (pre-container)

1. **Heartbeat** (`system/apps/trader/runner.py`): on every wake iteration,
   atomically write `now` (ISO) to `DATA_DIR/trader_heartbeat`
   (`Path(...).write_text(...)`; no fsync needed). Also write once at startup.
2. **Healthcheck helper** (`system/apps/trader/__main__.py`): add
   `python -m system.apps.trader healthcheck` subcommand — exits 0 iff
   `trader_heartbeat` exists and its mtime is < 10 minutes old. Used by the
   compose healthcheck (wake interval is 30 s).
3. **Monitor entrypoint** (`system/apps/monitor/__main__.py`): append
   `--server.address 0.0.0.0 --server.headless true` (overridable via env).
4. `.env.example`: document `BROKER=toss` semantics (real orders), and note
   `GOOGLE_REDIRECT_URI` stays `http://localhost:8501/oauth2callback`
   (SSH-tunnel friendly).
5. Tests: heartbeat file written by runner (one wake iteration),
   healthcheck exit codes (fresh/stale/missing file). Keep suite green.

## 2. Dockerfile (repo root)

Multi-stage, single image, two entrypoints:

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.13-bookworm-slim AS builder
WORKDIR /app
COPY pyproject.toml uv.lock README.md ./
COPY system ./system
RUN uv sync --frozen --no-dev --no-install-project

FROM python:3.13-slim-bookworm
# ta-lib >= 0.7 manylinux wheels bundle the native TA-Lib; if the wheel is
# unavailable at build time, fall back to building ta-lib 0.4.x from source
# (build-essential + wget in this stage) — document, don't commit hacks.
RUN useradd --create-home --uid 1000 app
WORKDIR /app
COPY --from=builder /app/.venv /app/.venv
COPY pyproject.toml uv.lock README.md ./
COPY system ./system
ENV PATH="/app/.venv/bin:$PATH" PYTHONUNBUFFERED=1 DATA_DIR=/app/data
USER app
```

- Entrypoints come from compose `command:`:
  trader → `python -m system.apps.trader`; monitor → `python -m system.apps.monitor`.
- Sanity: `docker run --rm img python -c "import talib, streamlit, tossinvest"`.
- Add `.dockerignore` (`.venv`, `data`, `.git`, `specs`, `notebooks`, `tests`).

## 3. Terraform (`terraform/`)

Files: `versions.tf`, `variables.tf`, `main.tf`, `outputs.tf`, `terraform.tfvars`
(gitignored, holds `project_id`, `owner_email`).

- **variables**: `project_id` (no default), `region = "us-central1"`,
  `zone = "us-central1-a"`, `owner_email` (no default),
  `vm_machine_type = "e2-micro"`, `vm_disk_gb = 16`, `repo_name =
  "quantitative-trading"`.
- **APIs**: `compute.googleapis.com`, `artifactregistry.googleapis.com`,
  `oslogin.googleapis.com`, `iap.googleapis.com`.
- **Artifact Registry**: `google_artifact_registry_repository`, format
  `DOCKER`, region `us-central1`, description.
- **Static IP**: `google_compute_address` named `quantitative-trading-ip`.
- **Service account** for the VM + project IAM bindings:
  `roles/artifactregistry.reader`, `roles/logging.logWriter`.
- **Owner IAM** (variable email): `roles/compute.osLogin`,
  `roles/iap.tunnelResourceAccessor`.
- **Instance**: `debian-cloud/debian-12` image, boot disk `pd-balanced` 16 GB,
  service account attached (no default access scopes — explicit scopes:
  `cloud-platform` read-only is not needed; use `logging.write` + none for
  storage, AR auth goes through metadata token with cloud-platform scope —
  set scope `cloud-platform` for simplicity), metadata `enable-oslogin=TRUE`,
  network tag `quantitative-trading-vm`.
- **Firewall**: single ingress rule — allow `tcp/22` from `35.235.240.0/20`
  to targets with that tag. Nothing else.
- **Outputs**: `vm_external_ip`, `artifact_registry_url`
  (`us-central1-docker.pkg.dev/<project>/<repo>`).

## 4. Ansible (`ansible/`)

- `ansible.cfg`: `inventory = inventory.ini`, `interpreter_python =
  auto_silent`, SSH retries.
- `inventory.ini` (generated by `just provision`): points Ansible at
  `127.0.0.1:2222` — a **background IAP tunnel** managed by `just tunnel-ssh`
  (idempotent: reuses an existing tunnel). The OS-Login username is resolved
  via `gcloud compute os-login describe-profile` after a warm-up
  `gcloud compute ssh --tunnel-through-iap` that registers the local key.
  Interactive access uses `gcloud compute ssh --tunnel-through-iap` directly;
  monitor port-forward: `just tunnel` (`ssh -L 8501:localhost:8501`).
- `group_vars/vm.yml`: `app_dir: /opt/quantitative-trading`,
  `image_base: us-central1-docker.pkg.dev/quantitative-trading-510302/quantitative-trading/app`.

### `bootstrap.yml` (idempotent, as-built)
1. apt: `ca-certificates curl gnupg unzip` (+ swapfile 2 GB: fallocate,
   mkswap, swapon, fstab entry — e2-micro has 1 GB RAM).
2. Docker Engine + compose plugin from Docker's official apt repo.
3. `/opt/quantitative-trading` + `data/` subdir, **owned by uid 1000** (the
   container's non-root `app` user; sqlite + heartbeat must be writable).
- **As-built deviation**: no Google Cloud SDK on the VM (the GCE image's own
  unsigned `google-cloud.list` repo conflicts with a signed one). Artifact
  Registry pulls authenticate via the VM service-account token from the
  metadata server (`docker login -u oauth2accesstoken`), performed in
  `deploy_tasks.yml` before each `docker compose pull`.
- **As-built deviation**: `just push` builds with
  `docker buildx build --platform linux/amd64 --push` — the VM is amd64 and
  the dev machine is arm64 (a native build produces `exec format error`).

### `deploy.yml` (tags: image, env)
1. Copy local **`.env.production`** → `{{ app_dir }}/.env` (mode 0600).
   (`.env` stays the local BROKER=mock file; the VM always gets the production
   file with BROKER=toss.)
2. Render `docker-compose.yml.j2` → `{{ app_dir }}/docker-compose.yml` with
   `image: {{ image_base }}:{{ tag }}` and `GOOGLE_REDIRECT_URI` unchanged.
3. Tag bookkeeping: if `current_tag` file exists and differs → write its value
   to `previous_tag`; write new `current_tag`.
4. `docker compose pull` + `docker compose up -d --remove-orphans`.
5. Wait for health: monitor `curl -fs localhost:8501/_stalive/health` (from the
   VM), trader container healthy; fail with details otherwise.

### `update.yml`
1. Read `current_tag` (new tag passed via `-e tag=...`).
2. Run steps 1–5 of deploy.yml.
3. On failure: **do not roll back automatically** — print the failed task,
   container logs (`docker compose logs --tail=50`), and:
   `Update failed. Previous tag preserved in previous_tag. Run: just rollback`.

### `rollback.yml`
1. Read `previous_tag`; abort if absent.
2. Render compose with the previous tag, `up -d`, health check, swap
   `current_tag`/`previous_tag` files.

### `docker-compose.yml.j2` (template)
```yaml
services:
  trader:
    image: {{ image_base }}:{{ tag }}
    command: python -m system.apps.trader
    env_file: .env
    volumes: [./data:/app/data]
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-m", "system.apps.trader", "healthcheck"]
      interval: 60s
      timeout: 10s
      retries: 3
  monitor:
    image: {{ image_base }}:{{ tag }}
    command: python -m system.apps.monitor
    env_file: .env
    volumes: [./data:/app/data]
    ports: ["127.0.0.1:8501:8501"]
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-c",
             "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8501/_stalive/health')"]
      interval: 60s
      timeout: 10s
      retries: 3
```

## 5. justfile (repo root)

All GCP recipes are shebang recipes starting with
`ctx use quantitative-trading`. Key recipes:

- `just build` — `docker build -t app:latest -t app:<git-sha> .` then tag both
  as `<ar_url>/app:{latest,<git-sha>}` (git-sha = `git rev-parse --short HEAD`,
  dirty tree → append `-dirty`).
- `just push` —
  `gcloud auth print-access-token | docker login -u oauth2accesstoken
  --password-stdin us-central1-docker.pkg.dev`, then push both tags.
- `just provision` — `terraform -C terraform init && terraform -C terraform
  apply`; parse `vm_external_ip` output → regenerate `ansible/inventory.ini`
  (template within the recipe).
- `just deploy` — `ansible-playbook ansible/bootstrap.yml ansible/deploy.yml
  -e tag=<git-sha>` (after build+push).
- `just update force=""` —
  1. guard (unless `force=--force`): Python one-liner or `date` with
     `TZ=Asia/Seoul`: reject if weekday Mon–Fri and 09:00 ≤ time < 15:30.
     Exit 1 with message `KRX market is open — update rejected (use
     'just update --force' to override)`.
  2. `just build && just push`
  3. `ansible-playbook ansible/update.yml -e tag=<git-sha>`
- `just rollback` — `ansible-playbook ansible/rollback.yml`
- `just status` — SSH: `docker compose -f {{app_dir}}/docker-compose.yml ps`
- `just logs service` — SSH: `docker compose logs --tail=100 <service>`
- `just tunnel` — start IAP tunnel and print the SSH port-forward command for
  the monitor (`ssh -L 8501:localhost:8501 <host>` via the same ProxyCommand);
  browser → `http://localhost:8501`.

## 6. Testing / Acceptance Criteria

1. `just provision` succeeds on the real project; `terraform apply` is
   idempotent on second run (no changes).
2. `just build` produces an image where
   `python -c "import talib, streamlit, tossinvest, pandas"` succeeds.
3. `just push` lists both tags in AR (verify via `gcloud artifacts docker
   images list`).
4. `gcloud compute ssh` (IAP) into the VM works with OS Login; `docker` and
   `gcloud auth configure-docker` in place; swap active (`free -h`).
5. `just deploy` brings up both containers: `just status` shows trader
   `(healthy)` (heartbeat) and monitor `(healthy)`; monitor port bound to
   `127.0.0.1:8501` only (`ss -tlnp | grep 8501`).
6. `just tunnel` + browser: Google login appears, authorized email sees all
   tabs; unauthorized email blocked. (Requires the Google OAuth client to
   have `http://localhost:8501/oauth2callback` as an authorized redirect URI.)
7. `just update` during KRX market hours (weekday 09:00–15:30 KST) exits 1
   with the rejection message; `just update --force` performs a real rolling
   update (new tag runs, `current_tag`/`previous_tag` updated).
8. Induced failure (e.g. bogus tag): `just update` exits non-zero, prints
   error info and the rollback hint; containers keep running the old tag;
   `just rollback` restores the previous tag.
9. `.env` on the VM has mode 0600 and is never in git; terraform state not in
   git.
10. Trader daemon on the VM logs `Next cycle at ...` and sleeps; with
    `BROKER=toss` no decision cycle is manually triggered during acceptance.
